## 📝 Пошаговая инструкция

### Шаг 0. Подготовка кейса

1. Создать папку для нового кейса:
```
.\Cases\ГГГГ-ММ-ДД_Case_Name\
```
2. Скопировать EML-файл в эту папку.
3. **НЕ ОТКРЫВАТЬ** файлы в пользовательских программах (Outlook, Word, Adobe Reader).

---

### Шаг 1. Анализ заголовков письма (Email Forensic)

**Инструмент:** `phishing-analysis` → `analyze_threats.py`

```bash
python src/utils/phishing_orchestrator.py "<путь_к_eml>"
```

**Что проверяется:**
| Параметр | Описание | Что искать |
|---|---|---|
| **SPF** | Проверка IP-адреса отправителя | Должен быть `PASS` |
| **DKIM** | Цифровая подпись домена | Должен быть `PASS` |
| **DMARC** | Политика домена | Должен быть `PASS` |
| **From** | Адрес отправителя | Совпадение домена с организацией |
| **Reply-To** | Обратный адрес | Не должен отличаться от From |
| **X-Mailer** | Почтовый клиент | Подозрительные клиенты |

**Красные флаги:**
- ❌ SPF=FAIL → Адрес подделан (spoofing)
- ❌ DKIM=NONE → Письмо не подписано, возможна подмена
- ❌ From и Reply-To не совпадают
- ❌ Отправитель с бесплатной почты (gmail, yandex) представляется организацией

---

### Шаг 2. Анализ тела письма

**Что проверяется:**
- Наличие ссылок и куда они ведут
- Скрытые перенаправления в HTML
- Признаки социальной инженерии (срочность, угрозы)
- Запрос персональных данных или паролей

**Красные флаги:**
- ❌ Ссылки ведут на домены, не связанные с отправителем
- ❌ Сокращённые URL (bit.ly, tinyurl)
- ❌ Слова: "срочно", "заблокирован", "подтвердите"
- ❌ Пустое тело с подозрительным вложением

---

### Шаг 3. Извлечение вложений

**Стандартные MIME-вложения** извлекаются автоматически на Шаге 1.

**Для писем Outlook с winmail.dat (TNEF):**
```python
# Требуется: pip install tnefparse
python src/utils/archive_extractor.py "<путь_к_eml>"
```

**Скрипт `extract_tnef.py`:**
```python
import email, os
from tnefparse import TNEF

with open("<eml_file>", 'rb') as f:
    msg = email.message_from_binary_file(f)

for part in msg.walk():
    if part.get_filename() == 'winmail.dat':
        tnef = TNEF(part.get_payload(decode=True))
        for att in tnef.attachments:
            name = att.name if isinstance(att.name, str) else att.name.decode('utf-8')
            with open(name, 'wb') as af:
                af.write(att.data)
            print(f"Extracted: {name}")
```

### Шаг 4. Глубокий анализ вложений

#### 4.1 PDF-документы

**Инструмент:** `pdf-forensics` → `deep_scan.py`

Проверяется:
- `/JavaScript` — встроенные скрипты
- `/OpenAction`, `/AA` — автозапуск при открытии
- `/URI` — скрытые ссылки
- `/EmbeddedFiles` — вложенные файлы внутри PDF
- `/Launch` — запуск внешних программ
- Обфусцированные HEX-теги (например, `/J#61vaScript`)

#### 4.2 DOC/DOCX документы

**Инструмент:** `full_doc_scan.py` (7-этапный сканер)

```bash
python main_launcher.py "<путь_к_doc>"
```

Проверяется:
| № | Что | Как определяется |
|---|---|---|
| 1 | **Формат** | Magic bytes: `D0CF11E0` = OLE, `504B0304` = DOCX |
| 2 | **VBA Макросы** | Сигнатуры: `AutoOpen`, `Document_Open`, `vbaProject` |
| 3 | **OLE-объекты** | `Ole10Native`, `Package`, `Equation` (CVE-2017-11882) |
| 4 | **Опасные API** | `powershell`, `cmd.exe`, `WScript`, `CreateObject`, `certutil`, `mshta` |
| 5 | **Внешние URL** | Кроме служебных `schemas.openxmlformats.org` |
| 6 | **UNC / SMB Пути** | Поиск `\\IP\`, `\\Host\`, `file://` (Кража NTLM-хэша) |
| 7 | **GPS-координаты** | Паттерн `NN.NNNN, NN.NNNN` |
| 8 | **HEX-инъекции** | Паттерн `0xXX, 0xYY, ...` |

**Красные флаги для DOC:**
- ❌ `AutoOpen` / `Document_Open` → Макрос запустится при открытии
- ❌ `Equation` → Уязвимость CVE-2017-11882 (RCE)
- ❌ `powershell` / `cmd.exe` → Дроппер
- ❌ `XMLHTTP` / `URLDownloadToFile` → Загрузчик
- ❌ **UNC-пути (`\\10.x.x.x`)** → Попытка кражи NTLM-хэша через SMB-запрос
- ❌ **file://** в ссылках на изображения или внешние ресурсы

#### 4.3 Изображения (JPG, PNG, GIF, BMP)

**Инструмент:** `media-forensics` → `analyze_image.py`

Проверяется:
- Trailing data (данные после маркера конца файла)
- Скрытые строки и команды
- Стеганография
- **Внешние источники**: Проверка, не является ли изображение ссылкой на внешний SMB-ресурс (`file://\\IP\image.png`)

---

### Шаг 5. Карвинг метаданных, скрытых HEX-инъекций и GPS-координат

**Инструмент:** `src/utils/string_extractor.py` / `01_Core_Engines/metadata_hex_scanner.py`

```bash
python src/utils/phishing_orchestrator.py "<путь>"
```

**Алгоритм работы сканера метаданных и HEX-потоков:**

1. **Metadata Carving** — чтение всех полей метаданных PDF (Subject, Author, Title, Keywords) на предмет HEX-данных вида `0xFF, 0xD8, 0xFF...`. Если найдены — декодирование и сохранение скрытого файла.

2. **GPS Extraction** — поиск координат `NN.NNNN, NN.NNNN` в бинарных строках файлов. Используется для определения "места встречи" или скрытой передачи геолокации.

3. **Strings Heuristics** — поиск подозрительных текстовых фрагментов (длина ≥ 8 символов) в бинарном потоке: PowerShell-команды, SQL-инъекции, URL-адреса.

---

### Шаг 6. Карвинг изображений

**Инструмент:** `carve_images.py`

```bash
python src/utils/image_carver.py "<путь_к_файлу>"
```

Извлекает все встроенные изображения по сигнатурам:
`JPEG (FFD8FF)`, `PNG (89504E47)`, `GIF (GIF8)`, `BMP (BM)`, `EMF`, `WMF`

Каждое извлечённое изображение затем проходит проверку media-forensics.

### Шаг 7. Песочница (опционально)

Если статический анализ вызывает сомнения:

1. **ANY.RUN** — загрузить файл на https://app.any.run
   - Наблюдать за поведением при открытии
   - Проверить сетевые соединения (все должны быть whitelisted)
   - Проверить процессы (не должно быть powershell.exe, cmd.exe)

2. **VirusTotal** — загрузить файл на https://www.virustotal.com
   - Проверить хеш-сумму по 70+ антивирусным движкам

### Шаг 8. Составление отчёта

Сохранить файл `ANALYSIS_REPORT.md` в папку кейса. Обязательные разделы:

1. **Общая информация** — тема, отправитель, дата, размер
2. **Хеш-суммы** — MD5, SHA-256 для EML и каждого вложения
3. **Проверка подлинности** — SPF, DKIM, DMARC
4. **Цепочка доставки** — Received-заголовки
5. **Анализ тела** — ссылки, текст
6. **Анализ вложений** — по каждому файлу отдельный блок
7. **Карвинг метаданных, HEX и GPS** — результаты глубокого сканирования
8. **Итоговое заключение** — CLEAN / SUSPICIOUS / MALICIOUS

## 📊 Матрица решений

| Результат | Действие |
|---|---|
| SPF=PASS, DKIM=PASS, нет макросов, нет JS | 🟢 **CLEAN** — безопасно |
| DKIM=NONE, но SPF=PASS, файлы чисты | 🟡 **Низкий риск** — уведомить отправителя о DKIM |
| Макросы VBA без опасных API | 🟡 **SUSPICIOUS** — не открывать, проверить в песочнице |
| VBA + Shell/PowerShell/CreateObject | 🔴 **MALICIOUS** — заблокировать, сообщить в ИБ |
| JavaScript в PDF + OpenAction | 🔴 **MALICIOUS** — заблокировать |
| Equation Editor в DOC (CVE-2017-11882) | 🔴 **CRITICAL** — эксплойт, сообщить в CERT |
| **UNC/SMB ссылки (file://\\IP)** | 🔴 **CRITICAL** — попытка кражи NTLM, блокировать IP |
| HEX-данные в метаданных PDF | 🟠 **Стеганография** — извлечь и изучить содержимое |
| GPS-координаты в бинарном потоке | 🟠 **OSINT** — определить локацию, оценить контекст |

> 1. **НИКОГДА** не открывайте подозрительные файлы в пользовательских программах
