# 🧩 Multi-Document Payload Assembly Detection (Анализ распределенных полезных нагрузок)

## 1. Концепция и векторы угрозы
В сложных целевых кампаниях (APT / Advanced Threat Actors) злоумышленники избегают отправки явных исполняемых файлов или очевидных макросов в одном документе. Вместо этого применяется **фрагментация полезной нагрузки между несколькими файлами в одном письме или серии сообщений**:

1. **Staged Assembly (Сборщик + Доноры):**
   * Документ A (DOCX/XLSX/LNK) содержит макрос/скрипт (Stage 0 Assembler), в котором нет самого тела вредоноса.
   * Документ B (PDF) и Документ C (XLSX) содержат «чистые» бизнес-данные, но в их структурах спрятаны закодированные блоки (в оверлеях после `%%EOF`, в скрытых XML-нодах `customXml`, в EXIF-метаданных картинок или в ячейках скрытых листов).
   * Скрипт-сборщик обращается к соседним файлам (`FileSystemObject`, `ADODB.Stream`, `copy /b`) и восстанавливает бинарный PE/DLL файл.
2. **Polyglot / Binary Splicing (Склейка файлов):**
   * Файлы намеренно разбиваются на сегменты, которые по отдельности не вызывают срабатывания шлюзовых антивирусов, но при конкатенации образуют исполняемый PE-файл или обфусцированный скрипт (PowerShell/VBS).
3. **Cross-Document Steganography:**
   * Несколько изображений из разных документов несут части ключа расшифрования или части шеллкода в LSB-каналах.

## 2. Обязательный чеклист для субагентов при анализе мульти-вложений

При наличии **двух и более вложений** в письме субагент ОБЯЗАН провести сквозную проверку кластера:

### Шаг 1. Проверка хвостовых оверлеев (Trailing / Overlay Data)
* **В PDF-документах:** Проверить байты после финального маркера `%%EOF`. Легитимный PDF заканчивается сразу после `%%EOF`. Наличие неструктурированных байт > 64 байт высокой энтропии — признак внедренного пейлоада.
* **В ZIP / OOXML (DOCX, XLSX):** Проверить смещение End of Central Directory (`PK\x05\x06`). Байты за пределами EOCD не парсятся офисными приложениями, но могут быть прочитаны сборщиком.

### Шаг 2. Поиск взаимных перекрестных ссылок (Cross-File References)
* Проверить тело, скрипты, формулы и свойства каждого файла на предмет упоминания имен других файлов кластера:
  * Поиск строк: `ActiveWorkbook.Path`, `Scripting.FileSystemObject`, вызовы Win32 API `FindFirstFile`, `CreateFile`.
  * Поиск прямых ссылок на имена соседних вложений (`.xlsx`, `.pdf`, `.png`, `.docx`).

### Шаг 3. Детектирование команд сборки и конкатенации
* Проверить документы на наличие команд:
  * `copy /b file1 + file2 payload.exe`
  * `type file2 >> file1`
  * `certutil -decode`
  * `[System.IO.File]::WriteAllBytes`
  * `ADODB.Stream` / `BinaryStream`

### Шаг 4. Поиск фрагментов исполняемых заголовков
* Сканирование всех неисполняемых файлов на скрытые сигнатуры:
  * Наличие `This program cannot be run in DOS mode` в не-PE файлах.
  * Наличие маркеров PE-заголовка `PE\0\0` с валидным смещением в e_lfanew (`0x3C`).
  * Высокоэнтропийные Base64-блоки длиной > 512 символов в нетипичных метаданных.

## 3. Автоматизированная интеграция в PhishingEngine

В пакете `01_Core_Engines/phish_engine` проверка кластера реализована методом:
`AttachmentsChecker.check_attachments_cluster(attachments)`

* **Генерируемые события:**
  * `ATT_CROSS_FILE_REFERENCE` (Severity: HIGH, Weight: 55) — документ ссылается на соседей.
  * `ATT_ASSEMBLY_COMMANDS` (Severity: CRITICAL, Weight: 80) — обнаружены команды склейки.
  * `ATT_PDF_SUSPICIOUS_OVERLAY` (Severity: MEDIUM, Weight: 35) — оверлей в PDF.
  * `ATT_ZIP_SUSPICIOUS_OVERLAY` (Severity: MEDIUM, Weight: 35) — оверлей в архиве.
  * `ATT_HIDDEN_PE_EXECUTABLE` (Severity: CRITICAL, Weight: 90) — скрытый исполняемый код в документах.
