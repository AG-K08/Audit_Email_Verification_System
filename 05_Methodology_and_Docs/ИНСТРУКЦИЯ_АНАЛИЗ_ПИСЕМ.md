## 📝 Пошаговая инструкция

### Шаг 0. Подготовка кейса

1. Создать папку для нового кейса:
```
.\Cases\ГГГГ-ММ-ДД_Case_ID\
```
2. Скопировать EML-файл в эту папку.
3. **НЕ ОТКРЫВАТЬ** файлы в пользовательских программах (Outlook, Word, Adobe Reader).

---

### Шаг 1. Анализ заголовков письма (Email Forensic)

**Инструмент:** `phishing-analysis` → `analyze_threats.py`

```bash
python 01_Core_Engines/analyze_threats.py "<путь_к_eml>"
```

**Что проверяется:**
| Параметр | Описание | Что искать |
|---|---|---|
| **SPF** | Проверка IP-адреса отправителя | Должен быть `PASS` |
| **DKIM** | Цифровая подпись домена | Должен быть `PASS` |
| **DMARC** | Политика домена | Должен быть `PASS` |
| **From** | Адрес отправителя | Совпадение домена с организацией |
| **Reply-To** | Обратный адрес | Не должен отличаться от From |
| **X-Mailer** | Почтовый клиент | Подозрительные клиенты |

**Красные флаги:**
- ❌ SPF=FAIL → Адрес подделан (spoofing)
- ❌ DKIM=NONE → Письмо не подписано, возможна подмена
- ❌ From и Reply-To не совпадают
- ❌ Отправитель с бесплатной почты (gmail, yandex) представляется организацией

---

### Шаг 2. Анализ тела письма

**Что проверяется:**
- Наличие ссылок и куда они ведут
- Скрытые перенаправления в HTML
- Признаки социальной инженерии (срочность, угрозы)
- Запрос персональных данных или паролей

**Красные флаги:**
- ❌ Ссылки ведут на домены, не связанные с отправителем
- ❌ Сокращённые URL (bit.ly, tinyurl)
- ❌ Слова: "срочно", "заблокирован", "подтвердите"
- ❌ Пустое тело с подозрительным вложением

---

### Шаг 3. Извлечение вложений

**Стандартные MIME-вложения** извлекаются автоматически на Шаге 1.

**Для писем Outlook с winmail.dat (TNEF):**
```python
# Требуется: pip install tnefparse
python 01_Core_Engines/extract_attachments.py "<путь_к_eml>"
```

**Скрипт `extract_tnef.py`:**
```python
import email, os
from tnefparse import TNEF

with open("<eml_file>", 'rb') as f:
    msg = email.message_from_binary_file(f)

for part in msg.walk():
    if part.get_filename() == 'winmail.dat':
        tnef = TNEF(part.get_payload(decode=True))
        for att in tnef.attachments:
            name = att.name if isinstance(att.name, str) else att.name.decode('utf-8')
            with open(name, 'wb') as af:
                af.write(att.data)
            print(f"Extracted: {name}")
```

### Шаг 4. Глубокий анализ вложений

#### 4.1 PDF-документы

**Инструменты:** `01_Core_Engines/metadata_hex_scanner.py`, `03_Clients_and_Integrations/Distributable/src/utils/pdf_scanner.py`

Проверяется:
- `/JavaScript` — встроенные скрипты
- `/OpenAction`, `/AA` — автозапуск при открытии
- `/URI` — скрытые ссылки
- `/EmbeddedFiles` — вложенные файлы внутри PDF
- `/Launch` — запуск внешних программ
- Обфусцированные HEX-теги (например, `/J#61vaScript`)

#### 4.2 DOC/DOCX документы

**Инструменты:** `full_doc_scan.py`, `olevba`, `office_analyzer.py` (OMSA), `01_Core_Engines/analyze_email_full.py`, `01_Core_Engines/office_document_threats.py`

```bash
python 01_Core_Engines/full_doc_scan.py "<путь_к_doc>"
python -m oletools.olevba --decode --reveal "<файл>"
python 02_Office_Macro_Analyzer_OMSA/office_analyzer.py "<файл>"
```

> **Важно:** отсутствие VBA-макросов (`olevba`: *No macros*) **не означает безопасность**. Семейства вроде `Trojan-Downloader.MSOffice.Agent` часто используют внешние шаблоны, OLE-объекты и поля Word без классических макросов. При сомнениях — **обязательна песочница** (KATA, ANY.RUN).

Проверяется:

| № | Что | Как определяется |
|---|---|---|
| 1 | **Формат** | Magic bytes: `D0CF11E0` = OLE, `504B0304` = DOCX |
| 2 | **VBA Макросы** | `olevba`: `AutoOpen`, `Document_Open`, `vbaProject` |
| 3 | **OLE-объекты** | `Ole10Native`, `Package`, `Equation` (CVE-2017-11882), вложенные `\x01Ole` |
| 4 | **Опасные API** | `powershell`, `cmd.exe`, `WScript`, `CreateObject`, `certutil`, `mshta` |
| 5 | **Внешние URL** | Кроме служебных `schemas.openxmlformats.org`, `microsoft.com` |
| 6 | **UNC / SMB Пути** | Поиск `\\IP\`, `\\Host\`, `file://` (Кража NTLM-хэша) |
| 7 | **GPS-координаты** | Паттерн `NN.NNNN, NN.NNNN` |
| 8 | **HEX-инъекции** | Паттерн `0xXX, 0xYY, ...` |

##### 4.2.1 Remote Template Injection (внешние шаблоны)

Атака: документ при открытии подгружает **внешний шаблон** по HTTP/HTTPS; код выполняется в контексте Word без видимых макросов в файле.

**Где искать (DOCX):**
- `word/_rels/document.xml.rels` — связь `Type` = `.../attachedTemplate`, `Target="http(s)://..."`
- Другие `*.rels` с `TargetMode="External"`

**Где искать (DOC OLE):**
- Строки `attachedTemplate`, внешние URL в потоках `WordDocument`, `1Table`, `Data`
- **UTF-16LE:** URL шаблона часто закодирован как `h\x00t\x00t\x00p\x00...` (не виден в ASCII-`strings`)
- Сетевые обращения при открытии (только в песочнице): `WINWORD.EXE` → внешний IP/домен

**Команды:**
```bash
# DOCX: извлечь и просмотреть связи
unzip -p file.docx word/_rels/document.xml.rels | findstr /i "attachedTemplate Target http"
python 01_Core_Engines/office_document_threats.py "<файл>"

# Безопасный полный разбор (in-memory, Word не запускается):
python 01_Core_Engines/safe_office_deep_scan.py "письмо.eml"
python 01_Core_Engines/safe_office_deep_scan.py "вложение.doc" --stdout
```

**Пример (образец документа с подгрузкой внешнего шаблона):**
- Классических макросов нет (`olevba` — clean)
- В потоке `1Table` обнаружен URL в кодировке UTF-16LE: `https://malicious-template.example.com/payload/template.dotm`
- При открытии в изолированной песочнице процесс `WINWORD.EXE` инициирует сетевое соединение к `203.0.113.50:443`

**Красные флаги:**
- ❌ `attachedTemplate` + `http(s)://` на сторонний домен
- ❌ Word обращается в сеть к не-Microsoft домену при открытии (KATA/VirusTotal)

##### 4.2.2 Встроенные OLE-объекты

**Типы угроз:**
| Маркер | Риск |
|--------|------|
| `Ole10Native` | Встроенный бинарный объект (exe, скрипт) |
| `Package` | Упакованный файл внутри документа |
| `Equation.3` | Equation Editor — CVE-2017-11882 (RCE) |
| Вложенный `\x01Ole` | Рекурсивные OLE-контейнеры |

**Команды:**
```bash
python -m oletools.oledump "<файл.doc>"
oleid "<файл>"
```

**Красные флаги:**
- ❌ `Package` + исполняемое содержимое
- ❌ `Equation` в документе от неизвестного отправителя
- ❌ Несколько уровней вложенных OLE без деловой необходимости

##### 4.2.3 DDE и поля Word

**DDE** (Dynamic Data Exchange) — устаревший механизм; поля `DDE` / `DDEAUTO` могут запускать команды при обновлении поля или открытии документа.

**Где искать:**
- **DOCX:** `word/document.xml` — теги `<w:instrText>DDE AUTO ...</w:instrText>`
- **DOC OLE:** поток `WordDocument`, байт-маркер поля `0x13` перед `DDE` / `DDEAUTO`
- **XLSX:** формулы `=DDE(...)` в `xl/worksheets/*.xml`

**Команды:**
```bash
python -m oletools.olevba --decode "<файл>"
# DOCX:
unzip -p file.docx word/document.xml | findstr /i "DDE instrText fldSimple"
```

**Красные флаги:**
- ❌ `DDEAUTO` — автозапуск (CRITICAL)
- ❌ `DDE` + `cmd` / `powershell` / `mshta` в аргументах поля
- ❌ `HYPERLINK` / `INCLUDEPICTURE` на внешний URL в служебном документе

##### 4.2.4 Матрица: статика vs песочница

| Статический результат | Действие |
|----------------------|----------|
| `olevba` — макросов нет, но есть внешний URL / Template / DDE | 🟠 **SUSPICIOUS** → KATA |
| `olevba` — чисто, но отправитель подозрителен + `.doc` | 🟠 **SUSPICIOUS** → KATA |
| KATA: `Trojan-Downloader.MSOffice.Agent`, сеть из WINWORD | 🔴 **MALICIOUS** |
| Всё чисто + легитимный отправитель | 🟢 **CLEAN** (с оговоркой) |

##### 4.2.5 Безопасный поиск «что активирует сеть при открытии»

**Принцип:** не открывать документ в Word на рабочей станции. Анализ — в памяти или в изолированной VM.

| Шаг | Инструмент | Что ищет |
|-----|------------|----------|
| 1 | `oleid` | Тип файла, макросы, ObjectPool, Flash |
| 2 | **`oleobj`** | External relationships, OLE links, customUI |
| 3 | **`msodde`** | Поля DDE / DDEAUTO |
| 4 | `olevba` | VBA-макросы, AutoOpen |
| 5 | **`office_document_threats` / этап 5** | Template, DDE, URL (UTF-16LE в .doc) |
| 6 | **YARA / этап 6** | Сигнатуры по всем вложениям (`04_Detection_Rules/YARA`) |
| 7 | **Nuclei / этап 7** | URL из письма и Office (`40k-nuclei-templates`, теги phishing/malware/…) |
| 8 | **KATA / ANY.RUN** | Поведение при открытии, если статика неясна |

- После KATA: скачать URL шаблона из отчёта и прогнать `safe_office_deep_scan.py` на шаблоне

**Типичные триггеры сети при открытии Word:**

| Механизм | Статика находит? | Инструмент |
|----------|------------------|------------|
| Remote Template Injection | Да (URL в .rels или UTF-16 в .doc) | oleobj, office_document_threats |
| DDE / DDEAUTO | Да | msodde |
| VBA AutoOpen | Да | olevba |
| INCLUDEPICTURE / внешняя картинка | Частично | oleobj, бинарный поиск URL |
| Обфусцированный URL | Иногда только UTF-16 | safe_office_deep_scan |
| Только runtime | Нет | KATA |

**Красные флаги для DOC (сводка):**
- ❌ `AutoOpen` / `Document_Open` → Макрос запустится при открытии
- ❌ `Equation` → Уязвимость CVE-2017-11882 (RCE)
- ❌ `powershell` / `cmd.exe` → Дроппер
- ❌ `XMLHTTP` / `URLDownloadToFile` → Загрузчик
- ❌ **UNC-пути (`\\10.x.x.x`)** → Попытка кражи NTLM-хэша через SMB-запрос
- ❌ **file://** в ссылках на изображения или внешние ресурсы

### Шаг 5. Карвинг метаданных, скрытых HEX-инъекций и GPS-координат

**Инструмент:** `01_Core_Engines/metadata_hex_scanner.py`

```bash
python 01_Core_Engines/metadata_hex_scanner.py "<путь>"
```

**Алгоритм работы сканера (`metadata_hex_scanner.py`):**

1. **Metadata Carving** — чтение всех полей метаданных PDF (Subject, Author, Title, Keywords) на предмет HEX-данных вида `0xFF, 0xD8, 0xFF...`. Если найдены — декодирование и сохранение скрытого файла.

2. **GPS Extraction** — поиск координат `NN.NNNN, NN.NNNN` в бинарных строках файлов. Используется для определения "места встречи" или скрытой передачи геолокации.

3. **Strings Heuristics** — поиск подозрительных текстовых фрагментов (длина ≥ 8 символов) в бинарном потоке: PowerShell-команды, SQL-инъекции, URL-адреса.

## 📊 Матрица решений

| Результат | Действие |
|---|---|
| SPF=PASS, DKIM=PASS, нет макросов, нет JS | 🟢 **CLEAN** — безопасно |
| DKIM=NONE, но SPF=PASS, файлы чисты | 🟡 **Низкий риск** — уведомить отправителя о DKIM |
| Макросы VBA без опасных API | 🟡 **SUSPICIOUS** — не открывать, проверить в песочнице |
| VBA + Shell/PowerShell/CreateObject | 🔴 **MALICIOUS** — заблокировать, сообщить в ИБ |
| **olevba чисто, но DDE / Remote Template / внешний OLE** | 🟠 **SUSPICIOUS** — KATA обязательна |
| **KATA: MSOffice.Agent, сеть из WINWORD** | 🔴 **MALICIOUS** — блокировать хеш и C2 |
| JavaScript в PDF + OpenAction | 🔴 **MALICIOUS** — заблокировать |
| Equation Editor в DOC (CVE-2017-11882) | 🔴 **CRITICAL** — эксплойт, сообщить в CERT |
| **UNC/SMB ссылки (file://\\IP)** | 🔴 **CRITICAL** — попытка кражи NTLM, блокировать IP |
| HEX-данные в метаданных PDF | 🟠 **Стеганография** — извлечь и изучить содержимое |
| GPS-координаты в бинарном потоке | 🟠 **OSINT** — определить локацию, оценить контекст |
